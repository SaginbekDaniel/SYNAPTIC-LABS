# Interfaces and invariants

## Контракты ремедиации, 25 ноября 2026

- Синхронный POST /api/v1/datasets/import сохраняет ответ и поддерживает Idempotency-Key. Без явного ключа replay определяется по exact file SHA-256, нормализованным имени и boundary в рамках authenticated scope. Для осознанной копии используйте новый explicit key. История replay сохраняется без автоматического истечения. Неуспешная синхронная транзакция освобождает reservation.
- POST /api/v1/datasets/import-jobs принимает multipart и возвращает 202 с Location. Там доступны accepted, processing, completed, failed, cancelled. POST /api/v1/datasets/import-jobs/{id}/cancel отменяет только accepted. Новый explicit key позволяет повторить исправленный файл после terminal failure. Ошибки схемы и row quarantine доступны как отдельные состояния или report. Предел 20 MiB и 200 000 строк по умолчанию.
- POST /api/v1/analysis/jobs принимает profile experimental_context. Доступность проверенного контекста определяется серверным каталогом и точной версией dataset. Новые job закрепляют политику и digest до постановки в очередь.
- POST /api/v1/sandbox/transfers принимает UUID intent_id как ключ повтора в рамках tenant/subject. Customer reference берётся из verified principal. GET /api/v1/sandbox/transfers/{assessment_id} повторно открывает оценку. Подмаршрут evidence требует analyst/reviewer scope, actions принимает отдельный UUID action_id и может отдавать append-only acknowledgement. Для повторной оценки после отказа передаётся новый intent_id и supersedes_assessment_id.
- POST /api/v1/cases/{case_id}/feedback работает в authenticated analytics у независимого reviewer. Передайте expected_case_version, expected_alert_revision, expected_review_id (для коррекции), reason, outcome confirmed_fraud, confirmed_legitimate или insufficient_evidence. История рецензирования фиксируется в case audit с закреплённым evidence digest и snapshot. GET /api/v1/cases/{case_id}/feedback-label возвращает минимальную псевдонимизированную метку для активной независимой оценки, если настроен отдельный NEXORA_FEEDBACK_EXPORT_KEY длиной от 32 символов. Клиент должен хранить исторические экспорты в разрешённом реестре датасетов. Движок сам метки не потребляет.
- /health/live проверяет HTTP процесс. /health/ready сообщает database, schema, migration и expected_migrations отдельно. Схема, отличающаяся от release heads, даёт 503.

OpenAPI и client schema сгенерированы одним маршрутом экспорта. [Архитектура](../audit/remediation/ARCHITECTURE_V3.md) · [Сверка контрактов](../audit/remediation/evidence/final-static.log)

The OpenAPI document is the transport contract: `apps/web/openapi.json` (generated by
`scripts/export_openapi.py`), TypeScript types in `apps/web/src/lib/api-types.ts`
(`npm run gen:api`). This file states the invariants the schema cannot express.

## Money, identity, time

| Invariant | Where enforced |
|---|---|
| `amount_minor` is a positive integer of minor units; JSON carries it as a **decimal string** | `domain/money.py`, DB CHECK, DTO type `Money = str`, `lib/format.ts` (BigInt only) |
| Floats, signs, decimals, exponents are rejected at ingest | `parse_amount_minor` |
| Account/transaction ids are opaque strings, never numbers | `ingest/validation.py` rejects numeric types; UI renders verbatim |
| `time_precision='day'` ⇒ `occurred_at = null`; never display a clock time | DB CHECK, `ObservedTransfer.__post_init__`, `formatEventTime` |
| Timestamps require an explicit offset; stored UTC | `_parse_timestamp` |
| Only `posted` transfers enter aggregates and flows (reversal policy v1) | `ELIGIBLE_STATUSES` |
| Identical re-import = duplicate (no effect); same id + different content = quarantine | `prepare_batch`, `ingest_rows`, DB UNIQUE |

## Analysis outputs

| Object | Identity | Notes |
|---|---|---|
| Snapshot | uuid5(dataset, input manifest, config hash, graph version) | Includes transactions with `ingest_seq ≤ max_ingest_seq` |
| Formation | uuid5(snapshot, kind, currency, canonical members) | funnel: centre + sorted feeders; fan_out: distributor + sorted recipients; chain: ordered path; cycle: loop from its earliest edge |
| Evidence | uuid5(formation, role) | `transaction_ids` resolve via FK table |
| Alert | fingerprint sha256(dataset, kind, currency, members, family group, detector) | Snapshot-independent: reruns update, never duplicate |

Evidence kinds used: `graph_fact` (structure, `total_minor` recomputable), `temporal_fact`,
`statistical_fact` (peer statistics: `window_minor` recomputes from the cited transactions and
`burst_share_bp = window_minor·10000 // turnover_minor`), `counterevidence` (contradicted chronology,
or turnover typical of peers), `coverage_fact`. Consumers must pair evidence with reasons by
`reason_code` prefix (`STRUCT_`, `TEMPORAL_`, `PEER_`), never by kind alone.

Temporal observations: `entry_minor ≥ possible_compatible_minor ≥ strict_compatible_minor ≥ 0`,
`compatible_fraction_bp` (integer basis points), `lag_days_*` always, `lag_seconds_*` only
when every linked pair has source timestamps.

## Risk

`band ∈ {critical, high, medium, low, insufficient_evidence}`; `priority ∈ [0,100]` or
`null` iff `insufficient_evidence`. Reason codes are `{code, params}`; the UI renders text
from params only (`reasonText` in `lib/i18n.ts`). Alerts open for band ≥ `medium` and for
`insufficient_evidence`.

`BAND_CAPPED_BY_EVIDENCE` carries `gates` (risk-policy-v2): `temporal_unavailable`,
`temporal_ambiguous`, `temporal_contradicted`, `peer_contradicted`.

## Evaluation

`GET /api/v1/evaluation` returns the committed artifact of the last executed benchmark run
(`EvaluationReport`, `synthetic: true`, schema version 1) with per-dataset manifests removed.
`404 BENCHMARK_NOT_FOUND` when no run exists; `500 BENCHMARK_ARTIFACT_INVALID` for an unreadable
or unsupported artifact. The endpoint never computes metrics.

## Cases

States `new → investigating → {escalated, dismissed, closed}`, `escalated|dismissed → closed`,
`closed → reopened → investigating`. Reason required for escalated/dismissed/closed/reopened.
Every mutation sends `expected_version`; mismatch ⇒ `409 CASE_VERSION_CONFLICT`.
The decision and its audit event commit in one transaction.

## Errors

`{"error": {"code", "message", "request_id", "details"}}` with 404/409/413/422/503/500.
