# Experiment protocol — sealed evaluation `sealed-v1`

Status: **LOCKED** before the hypothesis engine was written. This file is committed in the same
commit as the sealed generator and the harness metrics, and that commit precedes every commit
that adds or tunes the hypothesis engine (verify with `git log --follow` on this file and on
`src/nexora/analytics/hypotheses/`). Changing anything below after the sealed run invalidates it.

## Why a new evaluation set

| Split | Seeds | Status |
|---|---|---|
| `bench-v1` dev | 1000–1029 | exposed: design and error analysis |
| `bench-v1` validation | 2000–2019 | exposed: inspected during v2 development |
| `bench-v1` holdout | 3000–3029 | **exposed**: its results were read during v2 development and are published. It is no longer an unbiased test and is not used for any decision in this work. |
| `sealed-v1` | 9000–9059 (60 datasets) | sealed: generated by an independently written generator; evaluated **once**, after the lock below |

Additional reasons `bench-v1` cannot certify new work (see `docs/architecture/LEAKAGE_ANALYSIS.md`):

* **L-01 boundary label leak**: `bench-v1` declares a collection boundary only on the centres of planted
  fraud, so every abstention is a true positive by construction (dev: 5/5 abstentions are planted fraud).
* **L-02 duplicate inflation**: P@K and alert precision count every duplicate alert on one network.
* **L-03 shared mechanisms**: the dev/validation/holdout splits come from one generator with one set of
  mechanisms; a heuristic that learns that generator transfers between its splits for free.

## Sealed generator (`sealed-gen-v1`)

`src/nexora/evaluation/sealed_generator.py`, sha256 at lock:
`558e3595239fc4e929fed5c34546044efcf88f0e015f2842c21350446e073e9f`

* written separately from `generator.py`; 45-day window, log-uniform amounts, fractional-day timing;
* 11 suspicious families (incl. adversarial: recurring-feeder mules, activation payments, slow
  collection, low-value coordination, a chain with one leg missing) and 9 legitimate families (incl.
  event ticketing and charity campaigns, which share every transaction-level property of a mule
  collection, payroll whose staff spend onward, cash pooling, lending, rent, marketplace with refunds);
* **label-blind coverage contract**: 6 % of *all* accounts are declared at the boundary, plus the
  centres of boundary scenarios;
* complete truth account lists; scenarios never share accounts (tested).

## Methods compared on the sealed split

1. **Baseline** — the configuration merged at `4c01a7a` (`detectors-v2`, `risk-policy-v2`), reconstructed
   by `config_variant` exactly as shipped.
2. **Candidate** — the configuration at the commit that runs the sealed evaluation (audit fixes plus,
   if adopted on dev, the hypothesis engine).
3. Simple baselines B0–B3 as in `bench-v1`, for context only.

## Metrics (all computed by `summarize`)

Primary: scenario recall, scenario FPR, high-band FPR, distinct-network P@5.
Secondary: scenario precision/F1, raw P@K, Recall@K, alerts/dataset, alerts per flagged network,
abstention rate and its suspicious share, partial-analysis rate, quarantined formations, latency,
per-family detection.

## Pre-registered decision rule

The candidate is reported as an **improvement** only if, on the sealed split, all hold:

1. scenario recall drops by at most 2 percentage points versus the baseline;
2. high-band FPR does not increase;
3. scenario FPR **or** distinct P@5 improves, with a paired bootstrap (datasets resampled, 2 000
   draws, seed fixed) 95 % interval for that difference excluding zero.

Otherwise the result is reported as *not demonstrated*, with the numbers, and no claim is made.
Per-family regressions are reported regardless of the aggregate outcome.

## Procedure

1. Develop and tune only on `bench-v1` dev. Validation/holdout are not consulted.
2. Freeze the candidate configuration and commit it.
3. Run `uv run python scripts/run_benchmark.py --splits sealed` once; commit the artifact unchanged.
4. If a defect is found in the harness *after* the run, the fix and a full rerun are documented as a
   protocol deviation; configuration may not change in response to sealed results.

## Known limits of this protocol

* The same team wrote the detectors and both generators. Independence is procedural (separate code,
  written before the engine, different mechanisms), not organisational. Results describe behaviour
  on synthetic data only and say nothing about accuracy on real bank data.
* 60 datasets give wide intervals for rare families; per-family numbers are descriptive.
